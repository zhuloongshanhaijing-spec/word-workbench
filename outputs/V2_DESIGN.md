# 每日录词工作台 v2 设计

## 已确认的产品规则

- 输入以 Mac 键盘为主；复习由 Anki 与 AnkiDroid 的内置调度完成，应用不计算遗忘周期。
- 应用内不再建立单词夹或单词书分类，直接创建和打开 Anki Deck。每个 Deck 独立卡片和独立复习进度；相同拼写进入不同 Deck 时创建不同卡。
- 默认卡正面只有英文词；卡背为中文义项、搭配和例句。没有反向拼写卡、音频、OCR。
- Apple Dictionary 是当前原始资料源；其原文必须保留。本地 Ollama `qwen3:8b` 根据原文生成候选中文卡背，用户可编辑后导入。
- Oxford、Cambridge 等只预留为未来来源适配器，不含密钥、网页抓取或预置连接。

## 数据与安全边界

- 每个 Deck 内的词条都有独立 UUID。Anki 更新只按该 UUID 找卡，因此不同 Deck 中同词不会合并。
- 每个词条保存 `rawDefinition` 与 `cardBack` 两层；AI 输出不会覆盖原始内容。
- 查不到的输入停在“纠错候选”状态，不写入词书。用户可选择候选、修改后重查，或明确添加一个空白的手工词条。
- 删除未导入词只删除本地词条；已导入词默认仅从本地书移除，Anki 卡保留并给出明确提示。物理删除 Anki 卡不在本版自动执行。

## 查询和整理流程

1. 输入单词后调用 Apple Dictionary。
2. 成功：新建本书的词条，保存完整原文，等待用户点“用 AI 整理”。
3. 失败：调用 macOS 拼写检查器和本地 qwen3:8b 取得候选；每个候选必须再通过 Apple Dictionary 查词；对输入与候选做字符级差异高亮；用户点击候选后再次查词。
4. AI：向本机 `http://127.0.0.1:11434/api/generate` 发送原文，要求严格 JSON，temperature 设为 0.1；应用验证 JSON 后把词性、义项、搭配、英中例句渲染为 HTML。
5. 用户可编辑最终卡背；批量整理当前 Deck 的全部待处理词；导入时自动启动并等待本机 Anki，再写到用户命名的 Deck。

## 可验证标准

- `mabrane` 不进入词书，出现可点击的候选与错误位置。
- 可在当前书中重新查询、编辑和移除未导入词。
- 新建/打开文件夹与书后，词条不泄漏到其他书。
- 同词加入两本书，Anki 产生两张独立卡并进入两个独立牌组。
- 原文、AI 卡背、手工编辑和重启后的书结构均能恢复。
- Ollama 不可用或返回无效 JSON 时，原文和手工编辑仍可使用。
